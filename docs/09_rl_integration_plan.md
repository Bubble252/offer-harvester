# 强化学习后续接入计划

## 当前结论

强化学习不进入 MVP 主链路。

原因：

- MVP 首要目标是跑通保研硕博申请 Web 工作流
- 当前强化学习代码只训练大纲和内容生成，不训练完整保研申请流程
- 当前训练数据量不足以支撑稳定产品效果
- PPTAgent 强化学习版本未接入主 PPT 生成链路

因此第一版采用：

```text
Prompt Baseline
-> Reviewer Check
-> User Edit
-> Evidence Audit
```

强化学习作为 V2 之后的增强能力。

## 接入目标

强化学习不用于预测录取，也不用于自动替用户决策。

适合优化的目标：

- 生成更稳妥的导师匹配分析结构
- 生成更符合保研场景的套磁邮件
- 生成更清晰的研究计划大纲
- 生成更适合面试展示的 PPT 大纲
- 降低模板化、夸大和无证据表达

不适合优化的目标：

- 自动判断录取概率
- 自动选择唯一最优导师
- 自动生成虚构经历
- 端到端替代完整申请流程
- PPT 视觉排版

## 数据积累阶段

MVP 需要从一开始记录可用于后续训练的数据，但不能影响主流程稳定性。

建议记录：

- 学生画像摘要
- 导师来源文本
- 导师结构化画像
- 匹配分析草稿
- 用户编辑后的匹配分析
- 套磁邮件草稿
- 用户编辑后的套磁邮件
- 面试问题草稿
- PPT 大纲草稿
- 材料质量检查结果
- 用户是否采纳
- 申请状态变化

注意：

- 真实学生资料默认不用于公开训练
- 训练数据需要匿名化
- 用户数据使用规则需要在隐私说明中明确

建议构造统一样本：

```json
{
  "sample_id": "rl_001",
```

## 奖励函数设计

### 规则奖励

适合自动计算：

- 是否引用真实导师来源
- 是否引用学生真实经历
- 是否避免“保证录取”“稳上”等表达
- 是否包含明确申请目标
- 是否结构完整
- 是否没有编造论文、成绩、奖项
- 是否避免过长、空泛、模板化

示例：

```text
reward = factuality_score
       + advisor_source_score
       + structure_score
       + tone_score
       - exaggeration_penalty
       - unsupported_claim_penalty
```

### LLM-as-Judge 奖励

适合人工难以写死规则的维度：

- 导师方向匹配度
- 申请语气是否稳妥
- 是否像真实学生写给真实导师
- 是否有具体证据
- 是否过度营销
- 是否适合后续面试解释

Judge 输出应限制为结构化 JSON：

```json
{
  "score": 8,
  "factuality_risk": "low",
  "advisor_fit": "high",
  "tone": "appropriate",
  "issues": []
}
```

## 优先训练任务

### 1. 导师匹配分析结构

输入：

- 学生画像
- 导师画像
- 导师来源摘要

输出：

- 匹配结论
- 优势
- 短板
- 推荐动作
- 证据引用

训练目标：

- 更稳定地产生 evidence-based 分析
- 避免录取概率表达

### 2. 中文套磁邮件

输入：

- 学生画像
- 导师方向
- 申请目标
- 匹配分析

输出：

- 邮件标题
- 邮件正文
- 附件建议

训练目标：

- 语气正式、克制、具体
- 不模板化
- 不编造经历

### 3. 面试 PPT 大纲

输入：

- 学生画像
- 导师画像
- 匹配分析
- 展示时长

输出：

- 3/5 分钟 PPT 大纲
- 每页讲述重点
- 每页证据来源

训练目标：

- 结构清楚
- 不堆文字
- 面向导师方向

### 4. 研究计划大纲

输入：

- 学生科研经历
- 导师方向
- 近期论文关键词

输出：

- 研究问题
- 背景
- 方法设想
- 可行性
- 与导师方向关系

训练目标：

- 不空泛
- 不超出学生能力太远
- 适合保研面谈

## 接入方式

强化学习模型上线时不直接替换现有生成流程，而是作为候选生成器。

推荐链路：

```text
Baseline Prompt 输出
RL-Optimized 输出
Reviewer 对比
选择更优版本
用户最终编辑
记录反馈
```

只有当离线评估稳定优于 baseline，才将 RL 输出设为默认版本。

## 评估指标

离线指标：

- 事实一致性
- 导师方向匹配
- 结构完整度
- 语气稳妥性
- 模板化程度
- 用户可编辑性
- 面试可解释性

线上反馈：

- 用户是否采纳
- 用户编辑幅度
- 是否进入下一阶段
- 是否收到导师回复

注意：导师回复率受很多外部因素影响，只能作为弱信号，不能作为唯一奖励。

## 与 PPTAgent 强化学习版本的关系

现有强化学习版本可作为参考：

- `outline/train_trl.py`
- `content/train_trl.py`
- GRPO/GSPO 训练方式
- 规则奖励 + DeepSeek Judge 的组合

但需要重新设计：

- 训练数据
- prompt
- reward
- task schema
- 中文保研业务约束

不直接复用其训练输出模型。

## 开发阶段

### V1：数据记录

- 在 MVP 中记录生成结果和用户编辑版本
- 记录 evidence
- 记录质量检查结果

### V2：离线评估

- 构造匿名样本集
- 建立 baseline
- 建立 judge prompt
- 对不同生成策略打分

### V3：训练实验

- 选择小模型
- 训练套磁邮件或 PPT 大纲任务
- 对比 baseline

### V4：灰度接入

- Web UI 中增加“实验版生成”
- 默认仍使用 baseline
- 用户可对比两个版本

## 风险控制

- 不使用未匿名化真实学生资料训练公开模型
- 不把申请结果当成唯一奖励
- 不训练录取概率模型
- 不允许 RL 模型绕过 evidence audit
- 不允许 RL 输出自动发送给导师
