# MVP 功能规格

## MVP 定位

第一版 MVP 是一个面向保研硕博申请的中文 Web 工作台。

目标是跑通一个完整闭环：

```text
学生上传资料
-> 添加真实导师信息
-> 创建申请目标
-> 生成匹配分析
-> 生成中文套磁邮件
-> 生成中文面试问题
-> 生成面试展示 PPT 大纲
-> 记录申请状态
```

MVP 不追求覆盖所有升学申请类型，优先解决保研硕博申请中最常见、最有价值的问题：

- 导师方向是否匹配
- 应该怎么写套磁邮件
- 面试可能被问什么
- 如何组织自我介绍和科研展示
- 多个目标如何追踪状态

## 用户范围

核心用户：

- 准备保研夏令营、预推免、九推的本科生
- 申请硕士、直博、博士培养路径的学生
- 需要围绕具体导师准备套磁和面试材料的学生

不作为 MVP 核心用户：

- 纯考研初试备考用户
- 海外申请全流程用户
- 已经入学后的科研管理用户
- 招生办或机构多人协作用户

## 语言范围

MVP 以中文为主。

必须支持：

- 中文学生画像
- 中文导师匹配分析
- 中文套磁邮件
- 中文面试问题
- 中文研究计划/个人陈述大纲
- 中文面试展示 PPT 大纲

暂缓：

- 英文 CV
- 英文套磁邮件
- 英文 PhD interview slides

## 输入材料

### 学生资料

MVP 支持用户上传或粘贴：

- 中文简历
- 成绩和排名信息
- 科研项目材料
- 论文/预印本/投稿说明
- 竞赛和获奖经历
- 个人陈述草稿

第一版可以先支持：

- PDF 上传
- Markdown / TXT 粘贴
- 手动补充表单

不强制支持：

- Word 复杂格式解析
- 图片证书 OCR
- 成绩单表格自动识别

### 导师资料

MVP 必须支持：

- URL 抓取
- 手动粘贴兜底
- 来源记录

来源类型：

- 导师主页
- 实验室主页
- 招生通知
- 夏令营通知
- 论文主页
- 学校教师主页
- 用户手动粘贴文本

URL 抓取失败时，系统必须让用户粘贴正文，而不是中断流程。

## 功能清单

### P0：必须实现

#### 1. 学生资料上传与画像生成

用户能力：

- 上传学生资料
- 粘贴补充文本
- 查看系统抽取的学生画像
- 手动修正画像字段

系统输出：

- 教育背景
- GPA / 排名
- 科研方向
- 项目经历
- 论文成果
- 竞赛奖项
- 技能关键词
- 风险项和缺口

验收标准：

- 用户可以看到可编辑的中文学生画像
- 系统不会把不确定信息当成事实
- 用户确认后的资料能被后续材料生成引用

#### 2. 真实导师资料采集

用户能力：

- 输入导师主页 URL
- 输入实验室主页 URL
- 输入招生通知 URL
- 粘贴导师资料正文
- 查看抓取状态
- 查看系统解析出的导师画像

系统输出：

- 导师姓名
- 学校学院
- 职称
- 实验室
- 研究方向
- 近期关注点
- 招生类型
- 邮箱
- 来源列表

验收标准：

- URL 抓取成功时保存正文和来源
- URL 抓取失败时允许手动粘贴
- 所有导师方向和招生信息能追溯到来源

#### 3. 创建申请目标

用户能力：

- 创建导师/实验室/项目目标
- 绑定导师资料来源
- 设置申请轮次
- 设置截止日期
- 设置目标类型：硕士、博士、直博、不确定

系统输出：

- 目标详情页
- 当前状态
- 下一步行动

验收标准：

- 一个学生可以管理多个目标
- 每个目标可以独立生成材料和状态记录

#### 4. 匹配度分析

用户能力：

- 对指定目标运行匹配分析
- 查看匹配等级
- 查看优势、短板和建议动作

系统输出：

- `strong_fit`
- `reasonable_fit`
- `weak_fit`
- `unknown`

分析维度：

- 研究方向匹配
- 导师近期方向匹配
- 学生项目经历匹配
- 成绩背景匹配
- 论文/竞赛支撑
- 面试风险
- 材料准备建议

验收标准：

- 不输出录取概率
- 不鼓励过度冲刺
- 每个核心结论有证据来源

#### 5. 中文套磁邮件生成

用户能力：

- 选择目标导师
- 选择邮件语气：稳妥、正式、简洁
- 生成中文套磁邮件
- 手动编辑
- 保存版本

系统输出：

- 邮件标题
- 邮件正文
- 附件建议
- 风险提示

验收标准：

- 邮件必须引用学生真实经历
- 邮件必须贴合导师真实方向
- 不自动发送邮件
- 不编造论文、排名、奖项

#### 6. 中文面试问题生成

用户能力：

- 针对目标生成面试问题
- 按类型查看问题
- 保存准备记录

问题类型：

- 自我介绍
- 科研项目深挖
- 导师方向相关问题
- 简历真实性问题
- 缺口解释问题
- 英语问题扩展

验收标准：

- 问题来自学生资料和导师方向
- 对短板给出稳妥解释思路
- 不生成虚构经历答案

#### 7. 面试展示 PPT 大纲生成

MVP 先生成 PPT 大纲和每页内容，不强制第一版直接生成 PPTX。

推荐 5 页结构：

```text
1. 封面
2. 教育背景与能力概览
3. 代表科研/项目经历
4. 与目标导师方向的匹配
5. 未来研究计划与结束页
```

用户能力：

- 选择 3 分钟或 5 分钟版本
- 选择目标导师
- 生成中文 PPT 大纲
- 下载 Markdown

验收标准：

- 大纲符合面试场景
- 每页有明确标题、核心内容、讲述重点
- 不直接塞满文字

#### 8. 申请状态追踪

用户能力：

- 查看目标列表
- 更新状态
- 添加备注
- 设置下一步行动

状态：

```text
draft
researching
ready_to_contact
contacted
replied
materials_preparing
submitted
shortlisted
interview_scheduled
interview_done
accepted
rejected
withdrawn
```

验收标准：

- 能展示多个目标的状态
- 能记录最近联系时间和下一步行动

### P1：尽量实现

## 非功能要求

### 隐私

- `workspace/` 默认不进入 Git
- 示例数据必须匿名
- 不保存真实 API key
- 不自动发送套磁邮件

### 可追溯

- 导师信息必须记录来源
- 生成材料必须能追溯到学生资料和导师来源
- 匹配分析必须保留 evidence

### 稳定性

- URL 抓取失败不应阻断流程
- LLM 调用失败应有错误提示
- 未配置演示文稿生成能力时仍可生成 PPT 大纲

### 开源边界

- 不复制外部申请流程项目
- 不复制外部演示文稿生成项目
- `integrations/` 只放适配器和接口

## MVP 不做什么

- 不做录取概率预测
- 不做导师全网批量爬虫
- 不做自动发邮件
- 不做真实论文自动下载
- 不做多用户权限
- 不做强化学习在线推理
- 不保证 PPTX 第一版直接生成

## MVP 演示案例

演示流程：

```text
1. 上传匿名学生简历和科研项目
2. 输入真实导师主页 URL
3. 抓取失败时演示手动粘贴兜底
4. 系统解析导师研究方向
5. 创建一个直博申请目标
6. 生成匹配分析
7. 生成中文套磁邮件
8. 生成面试问题
9. 生成 5 页中文 PPT 大纲
10. 将目标状态改为 contacted
```

演示成功标准：

- 用户能在 Web UI 中完成全流程
- 所有生成材料都可编辑
- 所有关键结论都有来源
- 没有复制借鉴项目源码
