# 保研与升学申请工作台项目背景

## 项目定位

本项目计划将 `/home/bubble/agent/ai-job-search-master` 的申请流程自动化能力，与 `/home/bubble/agent/居丽叶简历项目2：PPTAgent` 的演示文稿生成能力结合，改造成一个面向保研硕博申请场景的 AI 申请工作台。

项目目标不是简单生成一份简历或一封套磁邮件，而是覆盖学生从自我画像建立、目标筛选、材料定制、导师沟通、面试展示到申请追踪的完整流程。

一句话定位：

> 面向保研硕博申请人群的 AI 申请工作台，帮助学生基于真实导师信息完成稳妥型导师匹配、材料定制、套磁沟通、面试准备和状态管理。

## 第一版服务边界

第一版主要服务保研中的硕博申请人群，以“稳”为主。

具体含义：

- 优先覆盖面向硕士、博士培养路径的夏令营、预推免、九推等保研申请流程
- 优先帮助学生筛选匹配度较高、材料能支撑、风险较低的导师、实验室和硕博项目
- 不主打激进冲刺策略，不包装成“逆袭神器”
- 不输出绝对录取概率，不承诺录取结果
- 不用虚构经历提升匹配度
- 所有导师和项目信息必须来自真实来源或用户提供的真实材料

第一版可以兼容考研复试和海外硕博申请的部分材料生成，但产品叙事、功能优先级和演示案例都聚焦国内保研中的硕博申请。

第一版材料语言以中文为主，英文材料作为后续扩展能力。系统可以保留英文 CV、英文自我介绍、英文面试问题等接口，但 MVP 优先保障中文套磁邮件、中文个人陈述、中文研究计划和中文面试展示 PPT 的质量。

## 目标用户

核心用户包括：

- 准备保研夏令营、预推免、九推并希望申请硕士或直博项目的本科生
- 需要准备导师面谈、项目答辩、科研展示的学生
- 需要围绕具体导师方向准备套磁和面试材料的学生

扩展用户包括：

- 准备考研复试的学生
- 非保研路径申请国内硕士、博士项目的学生
- 申请海外硕士、博士、交换项目的学生

潜在扩展用户包括：

- 高校升学指导老师
- 留学/保研咨询机构
- 实验室招生助理
- 学生社群或升学服务平台

## 用户痛点

升学申请和普通求职有相似的流程，但目标、材料和评价逻辑不同。典型痛点包括：

- 不知道哪些导师、项目、夏令营适合自己
- 不知道真实导师近期研究方向和自己的经历是否匹配
- 不知道自己的科研经历如何包装成有说服力的申请材料
- 不同导师方向不同，需要反复改套磁邮件、个人陈述和简历
- 项目经历很多，但不知道面试时应该重点讲什么
- 保研/复试 PPT 缺少结构，容易变成流水账
- 申请目标多，容易忘记截止时间、套磁状态和回复情况
- 面试问题高度个性化，通用题库帮助有限
- 学生容易过度包装，导致材料和真实经历不一致

本项目要解决的不是“写得更漂亮”，而是“更匹配、更真实、更可追踪、更能面向面试解释”。

## 产品核心流程

完整工作流如下：

```text
学生资料导入
-> 学生画像构建
-> 真实导师/项目资料采集
-> 目标导师/项目建库
-> 匹配度评估
-> 申请材料生成
-> 套磁与沟通管理
-> 面试展示 PPT 生成
-> 模拟面试与问答准备
-> 申请状态追踪
-> 复盘与补短板建议
```

第一阶段不追求所有功能同时上线，而是先形成一个能跑通的闭环：

```text
上传简历/成绩/科研材料
-> 添加一个真实目标导师、实验室或硕博项目
-> 录入导师主页、论文主页、实验室主页或招生通知
-> 生成匹配分析
-> 生成套磁邮件和定制材料摘要
-> 生成 3-5 分钟面试展示 PPT
-> 生成模拟面试问题
-> 记录申请状态
```

## 两个现有项目的角色分工

### ai-job-search-master 的可复用能力

`ai-job-search-master` 本质上是一个申请流程自动化框架，可借鉴到升学场景。

本项目不直接把 `ai-job-search-master` 改造成保研工具，而是以自有代码为主，适度借鉴其流程设计。只有底层、通用、边界清晰的功能模块才考虑复用。

可借鉴部分包括：

- 个人画像初始化流程
- 目标条目管理逻辑
- 申请匹配评分框架
- 材料定制生成流程
- drafter-reviewer 双 Agent 审阅机制
- 面试准备流程
- 申请状态追踪
- HTML 报告生成
- 文档目录结构与归档方式

可能直接复用的底层模块包括：

- PDF 验证或文本抽取工具
- HTML 报告生成逻辑
- 状态枚举与 tracker 测试思路
- 安全检查、模板校验等通用工具

不建议直接复用的部分包括：

- 面向求职网站的岗位搜索逻辑
- 求职 CV 和 Cover Letter 模板
- 丹麦市场相关的门户适配器
- 强绑定 Claude Code 命令的工作流描述

原项目中的“岗位”可以替换为：

- 导师
- 实验室
- 夏令营项目
- 推免项目
- 硕士/直博项目
- 复试院校专业

原项目中的“CV + Cover Letter”可以替换为：

- 中文简历
- 英文 CV
- 个人陈述
- 研究计划
- 套磁邮件
- 推荐信素材包
- 面试自我介绍
- 科研项目介绍

### PPTAgent 的可复用能力

`PPTAgent` 适合承担升学申请中的高价值展示材料生成。

本项目不直接在原 PPTAgent 上大改，而是优先通过适配层调用其稳定能力。对于 PPT 解析、生成、任务进度、下载等底层功能，可以视代码稳定性局部复用；对前端页面和业务流程则按保研场景重写。

可复用部分包括：

- 从 PDF 或文档中解析内容
- 学习参考 PPT 的版式和视觉风格
- 生成可编辑 PPTX
- 按页数和结构生成演示文稿
- 多阶段异步任务进度
- 文件上传、生成、下载链路
- PPT 质量评估思路

优先直接复用或适配的部分包括：

- PPTX 上传和保存
- PDF/PPT 文档解析
- PPT 生成任务进度 WebSocket
- PPTX 下载接口
- PPT 模板学习和生成链路

不建议直接复用的部分包括：

- 原始上传页的简单表单交互
- 与保研业务无关的通用 PPT 生成文案
- 尚未接入主链路的强化学习训练脚本

在升学场景中，PPTAgent 可以生成：

- 保研夏令营自我介绍 PPT
- 预推免面试展示 PPT
- 硕博导师面谈个人陈述 PPT
- 科研项目答辩 PPT
- 导师面谈研究计划 PPT
- 英文 PhD interview slides

## 推荐产品形态

第一版产品形态确定为 Web 工作台，而不是命令行工具。

原因：

- 目标用户多数不是程序员
- 文件上传、材料预览、状态追踪更适合 Web UI
- PPT 生成需要等待进度和下载结果
- 目标池、材料库、申请状态适合看板式管理
- 后续可以扩展机构版或多人协作版

第一版先实现本地 Web 应用：

```text
FastAPI 后端
Vue 前端
本地文件存储
Markdown/PDF/PPTX 导出
```

后续再考虑数据库、登录、多用户、云端部署。

## 项目边界

第一阶段明确不做或谨慎做的功能：

- 不自动承诺录取概率
- 不伪造科研经历、论文、成绩或奖项
- 不替学生自动发送套磁邮件
- 不自动爬取所有院校系统，但需要支持真实导师信息录入、解析和来源记录
- 不做黑箱录取决策
- 不生成无法被学生解释的夸张材料

系统应该坚持：

- 所有关键材料可追溯到用户提供的真实经历
- 所有导师方向和申请建议可追溯到真实导师主页、实验室主页、招生通知、论文列表或用户提供的可靠文本
- 所有推荐结论给出证据
- 所有邮件和申请材料由用户最终确认
- 面试准备强调“如何解释真实经历”，而不是编造答案

## 核心卖点

可以对外包装为：

- 一站式保研/升学申请工作台
- 保研硕博导师匹配与材料定制助手
- 面向科研经历的申请材料生成器
- 可生成面试展示 PPT 的升学 Copilot
- 支持申请状态追踪和复盘的个人升学 CRM

最有差异化的卖点是：

> 不只写材料，还能根据目标导师方向定制材料，并生成可编辑的面试展示 PPT，同时追踪整个申请流程。

## 初步 MVP 定义

MVP 需要支持以下最小闭环：

- 创建学生档案
- 上传简历、成绩单、项目材料
- 创建目标导师或项目
- 输入真实导师主页、实验室主页、招生简章、论文主页或项目介绍
- 记录导师信息来源
- 输出匹配分析
- 输出套磁邮件草稿
- 输出定制版个人材料摘要
- 输出面试问题清单
- 调用 PPTAgent 生成自我介绍或科研展示 PPT
- 记录申请状态

MVP 完成后，应能演示一个完整案例：

```text
某计算机本科生准备申请某真实导师夏令营
-> 上传简历和科研项目
-> 输入导师主页、论文主页和招生通知
-> 系统生成匹配报告
-> 系统生成套磁邮件
-> 系统生成 5 页面试展示 PPT
-> 系统生成导师可能追问的问题
-> 看板记录该目标状态为“已套磁”
```
